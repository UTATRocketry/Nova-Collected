# Server layout

Where the ground station keeps its code, settings, config, data and logs. Live
state sits outside every code checkout, so deploying a different release never
touches it.

## Ops PC

| Path | What it is |
|---|---|
| `C:\Nova\` | This repo |
| `C:\Nova\ops\nova.settings.ps1` | **The** settings file: paths, ports, IPs, COM port, admin password. This PC's own copy; never committed |
| `C:\Nova\prod\backend\`, `prod\frontend\` | The prod stack's code, at the deployed release |
| `C:\Nova\dev\backend\`, `dev\frontend\` | The dev stack's code, on any branch |
| `C:\Nova\releases\<tag>\` | What each release pinned (`release.json`) and the config it was tested with |
| `C:\Nova\config\<env>\` | Live station config, edited from the web interface ([configs.md](../architecture/configs.md)) |
| `C:\Nova\config\history\` | Every config ever used (`snapshots\<hash>.yaml`) and `history.jsonl` |
| `C:\Nova\data\<env>\` | Raw recordings and their `.meta.json` |
| `C:\Nova\archive\<env>\<recording>\` | Self-contained recording bundles (data + config + meta) |
| `C:\Nova\state\prod.json` | Which release prod is running |
| `C:\Nova\logs\` | Every service's `.out.log` and `.err.log` |
| `C:\Nova\bin\` | WinSW and the per-service wrappers |
| `C:\Nova\releases.json` | Release index served by the console |
| `C:\Nova\console.json` | Console config |

> [!WARNING]
> `releases.json` and `console.json` are generated by `Nova.ps1`. Don't edit
> them by hand.

### Services

| Service | Component | Starts on boot |
|---|---|---|
| `mosquitto` | MQTT broker | yes |
| `nova-prod-backend` | backend | yes (delayed) |
| `nova-prod-frontend` | frontend | yes (delayed) |
| `nova-prod-fas` | FAS bridge | yes (delayed) |
| `nova-prod-console` | Nova Console | yes (delayed) |
| `nova-dev-*` | the same, for dev | no: started by `use dev` |

## Raspberry Pi

| Path | What it is |
|---|---|
| `/home/admin/prod/novaGround/` | What the service runs, at the deployed release |
| `/home/admin/dev/novaGround/` | Dev checkout, for tests |
| `/etc/nova/novaGround.env` | **The** settings file for the Pi |
| `/etc/nova/deployed` | Which release prod is running, written by `nova-pi.sh deploy` |
| `novaGround.service` | The systemd unit, installed by `nova-pi.sh install` |
| `start.sh` | Service entry point (systemd calls it) |
| `run.sh` | Interactive tmux session, for bench work |
